### CortexAI™ API Reference (Draft)

Note: All responses are JSON. Unless noted, endpoints may require `Authorization: Bearer <JWT>`.

## Emotion Analysis Service
- **POST** `/analyze`
  - Purpose: Analyze text for dominant emotion and screen for crisis language
  - Request: `{ "text": "I feel great" }` (1–5000 characters)
  - Response: `{ "emotion": "joy", "confidence": 0.98, "scores": { "joy": 0.98, "sadness": 0.01, "anger": 0.0, "fear": 0.0, "neutral": 0.01 }, "crisis_flag": false, "model": "SamLowe/roberta-base-go_emotions" }`
  - `emotion` is one of `joy`, `sadness`, `anger`, `fear`, `neutral`. `model` is `lexicon` when the keyword fallback is running.
  - Example:
    - `curl -X POST $EMO/analyze -H 'Content-Type: application/json' -d '{"text":"I feel great"}'`
- **GET** `/health` → `{ "status": "ok", "model": "..." }`

## Recommendation Service
- **POST** `/recommend`
  - Purpose: Recommend an exercise module and level based on mood
  - Request: `{ "user_id": "abc123", "mood": "sadness", "confidence": 0.9, "crisis_flag": false, "history": ["breathwork"] }`
    - Only `user_id` and `mood` are required. `history` lists previously recommended module IDs, oldest first.
  - Response: `{ "module": "mood_journaling", "level": "intro", "title": "Mood journaling", "description": "...", "minutes": 10, "reason": "mood_match", "alternatives": ["self_compassion_break", "gentle_movement"] }`
  - Rules: `crisis_flag: true` always returns `crisis_support`. A confidence below 0.4 is treated as `neutral`. Matching modules rotate by how often they appear in `history`, and the last one isn't repeated. The level goes up after 3 and 8 prior recommendations of the same module.
  - Example:
    - `curl -X POST $REC/recommend -H 'Content-Type: application/json' -d '{"user_id":"abc123","mood":"sadness"}'`
- **GET** `/health` → `{ "status": "ok" }`

## Companion Service
- **POST** `/reply`
  - Purpose: Short supportive reply to a check-in, generated by a local Ollama model
  - Request: `{ "text": "...", "emotion": "fear", "crisis_flag": false, "module_title": "Breathwork", "module_description": "..." }`
  - Response: `{ "reply": "...", "model": "llama3.2:3b" }`. `model` is `none` for the fixed crisis message and `fallback` when the output filter replaced the reply.
- **POST** `/ask`
  - Purpose: Answer a question from reviewed question-bank entries
  - Request: `{ "question": "How do I calm down?", "crisis_flag": false }`
  - Response: `{ "answer": "...", "sources": [ { "id": "breathwork-how", "question": "...", "score": 0.77 } ], "model": "llama3.2:3b" }`. With no matching entry, `sources` is empty and `model` is `none`.
- **GET** `/health` → `{ "status": "ok", "chat_model": "...", "embed_model": "...", "entries": 0, "include_drafts": false }`
- Both POST endpoints return 503 if Ollama is unreachable.

## Backend API
- Base URL: `$API`

### Auth
- **POST** `/auth/register`
  - Purpose: Create a user
  - Request: `{ "email": "user@example.com", "password": "secret" }`
  - Response: `{ "id": 1, "email": "user@example.com" }`

- **POST** `/auth/login`
  - Purpose: Obtain JWT
  - Request (form): `username=<email>&password=<password>`
  - Response: `{ "access_token": "...", "token_type": "bearer" }`
  - Example:
    - `curl -X POST $API/auth/login -d 'username=user@example.com&password=secret&grant_type=password' -H 'Content-Type: application/x-www-form-urlencoded'`

### Users
- **GET** `/users/me`
  - Purpose: Get current user profile
  - Response: `{ "id": 1, "email": "user@example.com" }`

- **GET** `/users/`
  - Purpose: List users (admin placeholder)
  - Response: `[ { "id": 1, "email": "..." }, ... ]`

### Sessions
- **POST** `/sessions/`
  - Purpose: Create a session record
  - Request: `{ "mood": "sadness", "duration_seconds": 600 }`
  - Response: `{ "id": 1, "user_id": 1, "mood": "sadness", "started_at": "...", "duration_seconds": 600 }`

- **GET** `/sessions/`
  - Purpose: List current user's sessions
  - Response: `[ { ... }, ... ]`

### Onboarding
- **POST** `/onboarding/`
  - Purpose: Create or update a lightweight onboarding profile by client-generated ID
  - Request: `{ "client_user_id": "local-guid", "display_name": "Alice", "age": 22 }`
  - Response: `{ "id": 1, "client_user_id": "local-guid", "display_name": "Alice", "age": 22, "created_at": "..." }`

- **GET** `/onboarding/{client_user_id}`
  - Purpose: Fetch onboarding profile by client ID
  - Response: `{ "id": 1, "client_user_id": "local-guid", "display_name": "Alice", "age": 22, "created_at": "..." }`

### Check-ins
- **POST** `/checkins/` (Bearer token)
  - Purpose: Analyze a short text, recommend an exercise, and record the result
  - Request: `{ "text": "I'm worried about tomorrow", "session_id": 3 }` (`session_id` optional; it must belong to the caller and gets its `mood` set)
  - Response: `{ "id": 1, "session_id": 3, "emotion": "fear", "confidence": 0.9, "crisis_flag": false, "module": "breathwork", "level": "intro", "created_at": "...", "title": "Breathwork", "description": "...", "minutes": 5, "alternatives": ["grounding_exercises", "progressive_muscle_relaxation"], "reply": "..." }`
  - The text is not stored. 404 if the session isn't the caller's; 503 if emotion analysis or recommendation is unreachable. `reply` is `null` if the companion is unavailable.

- **GET** `/checkins/` (Bearer token)
  - Purpose: List the caller's check-ins, newest first
  - Response: `[ { "id": 1, "session_id": 3, "emotion": "fear", "confidence": 0.9, "crisis_flag": false, "module": "breathwork", "level": "intro", "created_at": "..." } ]`

### Ask
- **POST** `/ask/` (Bearer token)
  - Purpose: Answer a question from the reviewed question bank. The question is screened with the emotion service's crisis check first.
  - Request: `{ "question": "How do I calm down?" }` (1–1000 characters)
  - Response: `{ "answer": "...", "sources": [ { "id": "breathwork-how", "question": "...", "score": 0.77 } ], "crisis_flag": false }`
  - Nothing is stored. 503 if the emotion or companion service is unreachable.

Notes:
- Use HTTPS. Set `Authorization` header with JWT for protected endpoints.
- Error schema (example): `{ "detail": "message" }`
